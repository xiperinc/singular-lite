01 / How it works

The right project knowledge,
for every model call.

The brain turns a project’s reviewed documents, code, run records and approved memory into a bounded, hash-bound context bundle. The host decides what each role receives, checks it at the moment of the call, and keeps a receipt.

02 / Memory and proof

Memory must be earned.
Retrieval is measured.

Crash-safe by construction

.singular-memory/
├─ records/      authoritative revision
├─ operations/   journal: prepared → committed
├─ checkpoints/  bounded recovery points
└─ index.json    derived · rebuild any time
  1. Lock, then finish any interrupted write.
  2. Replaying an operation ID returns the stored answer.
  3. Write the journal as prepared.
  4. Apply only onto the expected predecessor.
  5. Mark committed, then refresh the index.
  6. Readers take no lock, write nothing, and refuse while a journal is pending.

The bug it closes. Replaying an interrupted approval once revived a tombstoned record.

Retrieval is measured (B5)

14/14expected references included
0incorrect selections
2budget omissions, both declared
0deviations from labels

Negative control: one wrong expectation turns the run to deviated, exit 4. No model call is needed. Not yet covered: memory sources.

Built node by node

Opt-in. Unconfigured projects are unchanged. Project-local. No vector store or embeddings. Model output is a candidate, not truth. Documents can’t grant themselves authority. Readers never write. Safe in a sandbox. Retirement sticks through every rebuild.

What is live today. Campaign runs used this path with code-only context: 33 admitted bundles. Brain documents, memory and lookups are proven in tests and the 18-case evaluation, not yet in a live campaign. That is the next milestone.
